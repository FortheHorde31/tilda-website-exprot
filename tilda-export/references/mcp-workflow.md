# Процедура MCP

## Выбор страницы

Прочитай инструменты MCP, их описания и inputSchema. При другом префиксе сервера
ищи по смыслу. Прочитай проекты и страницы; сверь название, домен, project ID,
папку и alias с задачей. Не выбирай первый проект автоматически.

Для новой страницы проверь занятость адреса. Не переименовывай старую без поручения
на замену. Если есть `deployment.json`, сначала прочитай указанные в нём записи.
Отсутствие файла не означает, что предыдущая попытка ничего не создала.

Исторические названия — кандидаты для обнаружения, а не фиксированный контракт:

| Назначение | Инструменты |
|---|---|
| Проекты и страницы | `get_projects`, `get_pages`, `get_page_settings` |
| Новая страница | `add_blank_page` |
| Записи | `get_page_records`, `add_record` |
| Схема/текущие поля | `edit_record` |
| Изменение полей | `update_record` |
| Настройки/head | `update_page_settings`, `update_page_head_code` |
| Просмотр/публикация | `page_preview`, `publish_page` |

Ранее проверено: T123 «HTML-код» — tplid 131; T868 — tplid 868.
Надпись T123 не означает tplid 123. Подтверди тип через каталог/схему сервера.
Поля HTML обычно `code`, у попапа также `linkhook`; проверь их чтением блока.

## Запись

Создай один черновик и сразу сохрани page ID в локальный `deployment.json`.
Добавляй записи в порядке манифеста. После каждого создания сохраняй record ID.
Нативный попап не добавляй как обычный видимый T123.

Прочитай схему полей. Передай HTML строкой без повторного экранирования и обрезки.
Для обновления используй сохранённый record ID. Прочитай запись обратно, сравни
код с файлом, сохрани SHA-256 фактического кода и статус сверки. Если сервер
нормализовал строку, исследуй diff. Проверь hook, порядок, видимость и отсутствие дублей.

Перед изменением существующего содержимого сохрани текущие записи, настройки
и head, если он меняется. Укажи пути к копиям в deployment.json. Это снимки данных,
доступных через MCP, а не гарантированная полная резервная копия сайта.
Не обещай откат, если восстановление данных не поддерживается.

Перед изменением настроек прочитай всю форму. Некоторые версии
`update_page_settings` стирают поля, которые не передали. Сформируй запрос по
текущей inputSchema, сохрани title, description, alias, folder/date/sort,
canonical и OG, которые не нужно менять. Не отправляй сырой объект ответа
с полями вне схемы. Прочитай настройки после записи.
Не заменяй проектный head, аналитику, шапку и футер ради одной страницы.
Если манифест содержит head_file, подготовь безопасное объединение его содержимого
с текущим HEAD. Сохрани итоговый HEAD, запиши и сверь чтением. Проверь подключения
шрифтов/подсказки по [правилам скорости](performance.md), а не только их наличие в файле.

Если действие недоступно, назови пробел и возможный ручной шаг. Исторические
ограничения OG/header/footer/SEO не считай вечными. Заглушка T123 в `page_preview`
не доказывает работу интерактива. Не публикуй тестовую копию без поручения.

## Ошибки

- 401/403: останови запись. Проверь ключ, срок, проект и права. Не обходи ограничения.
- 429: следуй `Retry-After`/`retry_at`. Сохрани прогресс. Не обещай фиксированные
  «50 публикаций в час» для любого аккаунта. Не жди часами внутри активного вызова.
- Сетевой сбой: результат неизвестен. Прочитай страницу/записи и сверь состояние,
  прежде чем повторять создание. Не создавай дубли вслепую.
- Чтение не подтвердило запись: останови зависимые изменения и публикацию.
  После двух неудачных попыток одного действия сообщи причину и сохранённое состояние.

## Публикация и массовый перенос

Публикуй только порученную страницу, когда выпуск входит в запрос. Проверь комплект,
сверку после записи, адрес и настройки. Noindex меняй по задаче, не автоматически.

После публикации открой публичный HTTPS URL. Проверь ответ, фактическую версию,
визуальный результат и интерактив. HTTP 200 сам по себе не доказывает обновление.
При CDN-кэше сравни домен проекта Tilda и пользовательский домен. Сохрани адрес,
ID, время и результаты. Недоступность браузера оставляет визуальную проверку открытой.
Запиши результат проверки скорости отдельно. Статический аудит не заменяет замер.

Для массового переноса сначала проверь типовую страницу. Сохрани исходные тексты,
таблицы, картинки, SEO и карту URL. Храни состояние отдельно по каждой странице.
Для 3D проверь реальную scroll-сцену; для внешнего сервиса — backend URL и CORS.
Не публикуй весь сайт для проверки одного черновика.

Смена старого alias, снятие с публикации и редиректы требуют поручения на замену.
Перед изменением редиректов прочитай весь список и сохрани действующие правила.
Не удаляй старые страницы как способ отката.

Источник подключения: https://help-ru.tilda.cc/mcp. Механика полей также основана
на прежних рабочих прогонах; текущие схемы сервера и повторное чтение важнее.
