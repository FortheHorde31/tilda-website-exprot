# Подготовка блоков

Один независимый раздел — один HTML-фрагмент со своим стилем и уникальным корнем,
например `.launch-hero`. Не вставляй `<!doctype>`, `<html>`, `<head>` и `<body>`
в T123. Стили и скрипты допустимы внутри фрагмента.

Связанную scroll-сцену, canvas, HUD и скрипт держи одним блоком. Не дели их ради
одинакового размера файлов. Если сохраняешь собранный runtime, проверь публичные
URL JS chunks и CSS. Перевод на vanilla JS не обязателен; он должен сохранять функции.

## Стили и ресурсы

- Ограничь CSS корнем: `.launch-hero .title`. Не применяй reset `*`, `body`, `h1`
  ко всей странице. Нормализацию box-sizing делай под корнем.
- Каждый блок содержит нужные стили/токены. Общие шрифты можно загрузить один раз
  в head; отрази зависимость и сохрани прежний head. Не дублируй крупные библиотеки.
  Подготовку шрифтов, изображений и приоритетов выполняй по [правилам скорости](performance.md).
- Ресурсы должны иметь абсолютные HTTPS URL или подходящий data URI.
  Локальные относительные пути не работают после вставки в Tilda. Крупные фото,
  видео и шрифты не превращай автоматически в base64.
- Для внешних модулей используй версионированные URL. Не полагайся на importmap,
  пока её работа не проверена на целевой странице. Учитывай CSP и CORS.
- Скрипт ищет элементы в корне через `data-*` и защищён от повторного запуска.
  Уникальные `id` допустимы для якорей и доступности. Не дублируй их.
- Для координат страницы используй `getBoundingClientRect().top + scrollY`:
  `offsetTop` внутри `.t-rec` может считаться относительно записи Tilda.
- Проверь fixed/sticky внутри обёрток Tilda. Не добавляй глобальные исправления
  overflow без проверки. Следующие секции перекрывают fixed-сцену по дизайну.
- Аналитику и формы сохраняй по задаче, убирай только подтверждённые дубли.
  Серверные ключи не должны попадать в клиентский код. Для `postMessage`
  проверяй `event.origin` и `event.source`.

Справка: [HTML-блок T123](https://help-ru.tilda.cc/html). T123 и HTML-элемент
Zero Block — разные способы размещения кода; этот комплект загружает T123.
По справке Tilda исполнение кода нужно проверять на опубликованной странице.

## Попап

Для нативного HTML-попапа T868 файл содержит карточку, а не второй overlay.
Ссылка CTA и `linkhook` должны совпадать: `#popup:contact`. Каждому попапу нужен
уникальный hook. Собственный модал не требует T868, но требует проверки focus trap,
Escape, возврата фокуса и прокрутки.

Переопределяй контейнеры Tilda только с условием на свою карточку:

```css
.t-popup__container:has(.launch-contact),
.t-popup__container-animated:has(.launch-contact),
.t-popup__container-static:has(.launch-contact) {
  width: min(560px, calc(100vw - 32px));
  max-width: 560px;
  padding: 0;
  background: transparent;
}
```

Используй `!important` только при конфликте. На мобильном проверь left/right/margin
и обрезку карточки. Геометрию и breakpoint бери из дизайна. Обёртки могут меняться.

## Манифест

Смотри `assets/example/manifest.json`. Версия `1`, `blocks` — упорядоченный список.
`type: "html"` — T123, `type: "popup"` — нативный HTML-попап.
`file` — путь относительно манифеста; `root` — CSS-класс без точки;
`hook` — ссылка попапа. Манифест не содержит ключей и ID чужих проектов.
Он описывает комплект, но не является аргументом какого-либо инструмента MCP.
`head_file` необязателен: относительный путь к общим подключениям страницы.
`performance` содержит сведения о кандидате LCP; формат и ограничения описаны
в правилах скорости. Отчёт содержит предупреждения, а не балл PageSpeed.
