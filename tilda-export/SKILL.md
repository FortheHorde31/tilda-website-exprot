# Tilda Export + MCP

Перенеси готовую страницу в Тильду с сохранением дизайна, содержания и поведения.
Результат: файлы блоков, манифест, локальное превью, а при порученной загрузке —
проверенный черновик или опубликованная страница через MCP.

Скилл не требует проектов, доступов или других скиллов автора. Для локальной
проверки нужен Python 3.10+. Для аккаунта нужен официальный Tilda MCP.
Первый запуск: [установка и подключение](references/setup.md).

## 1. Определи вход и результат

Найди HTML, ресурсы и работающий способ сборки. Для React/Vue сначала получи
рабочую сборку: JSX нельзя вставить в T123 как HTML. Уточняй только недостающие
данные: исходники, целевой проект, адрес и результат — комплект, черновик, публикация.

Не меняй дизайн, тексты и функции только ради удобства переноса. Не удаляй
автоматически аналитику, cookie-баннер, формы и анимации. Проверь дублирование
на стороне проекта Tilda. T123 исполняет клиентский HTML/CSS/JS; серверный код
и хранение данных требуют отдельного backend.

До изменения HTML прочитай [правила скорости](references/performance.md).
Сохрани исходник, найди проблемы загрузки и составь performance-plan.json.
LCP без браузерного подтверждения отмечай как кандидат. Замер не подменяй анализом кода.

## 2. Подготовь блоки с учётом скорости

Следуй [правилам переноса](references/blocks.md). Создай новую папку экспорта
рядом с исходниками. Не перезаписывай оригинал.

- `tilda-static-blocks/01-hero.html`, `02-….html` — порядок секций страницы.
- `tilda-popup/…html` — карточки нативных попапов, если они нужны.
- `manifest.json` — порядок, пути, уникальные корни и hooks попапов.
- `head.html` — общие подключения/подсказки, если нужны; путь в `head_file` манифеста.
- `performance-plan.json` — находки, решения, причины и способ проверки скорости.
- `preview.html`, `checks.json` — локальное превью и результат проверки.
- `deployment.json` — реальные project/page/record ID, хэши, статус чтения
  после записи и публикации. Создавай только при работе с аккаунтом.

Формат и проверяемый пример находятся в `assets/example/`. Это пример структуры,
а не обязательный дизайн. Не копируй его тексты и цвета в пользовательскую страницу.
Границы блоков выбирай по DOM, стилям и зависимостям скриптов. Произвольный HTML
нельзя надёжно нарезать по одному регулярному выражению.

## 3. Проверь локально

Подставь фактический путь установленного скилла:

```sh
python3 <skill-dir>/scripts/check_export.py /path/to/export/manifest.json
```

Помощник проверяет структуру, пути, корни, якоря и hooks. При успехе создаёт превью
в приблизительных обёртках Tilda и отчёт с SHA-256 блоков. Это не полноценная
проверка CSS/JS, не скриншот и не рендер Tilda.

Статический аудит скорости встроен в тот же запуск. Разбери findings в разделе
performance отчёта: исправь проблему или запиши причину сохранения. Предупреждения
не означают измеренный дефект. Превью использует тот же head.html, что и комплект MCP.

Открой превью через локальный веб-сервер. Проверь широкую и узкую ширину,
например 1440/390 px: прокрутку, шрифты, картинки, формы, CTA, клавиатуру, попапы
и анимации. Если браузер недоступен, отметь визуальную проверку как невыполненную.

## 4. Загрузи через MCP

При порученной загрузке прочитай [процедуру MCP](references/mcp-workflow.md).
Используй инструменты подключённого сервера и их актуальные схемы.
Имена и числовые ID из примеров не заменяют обнаружение возможностей.

Подготовка блоков не разрешает менять аккаунт. Загрузка черновика не разрешает
публикацию. Если пользователь уже поручил публикацию конкретной страницы,
не спрашивай об этом повторно после проверок. Не расширяй задачу на другие страницы.

После изменения прочитай данные обратно. Перед перезаписью сохрани прежние данные.
После сетевого сбоя сначала выясни, что уже создано; не создавай дубли вслепую.
Если экспорт содержит head_file, безопасно объедини его с текущим HEAD страницы,
запиши через поддерживаемый MCP-инструмент и сверь повторным чтением.

## 5. Сдай результат

Дай путь к комплекту и ссылку, если она есть. Назови фактический статус:
подготовлен локально / загружен черновик / опубликован и проверен.
Укажи оставшиеся ограничения. Для массового переноса сначала проверь одну
типовую страницу, затем продолжай по сохранённому состоянию.
Приложи performance-report: изменения, сохранённые решения, выполненные проверки
и замеры. Если скорость не измерена, назови это явно. После порученной публикации
проверь действительную загрузку и версию страницы по правилам скорости.
